# ЧАСТЬ I. ОБЩИЕ СВЕДЕНИЯ

## 1.1. Наименование и назначение

**Excel Studio HR** — desktop-приложение для Windows, обеспечивающее полный цикл работы с кадровыми Excel/CSV-отчётами, поступающими от обособленных площадок (ОП) строительной компании:

```
приём (Outlook/папки/буфер) → распознавание структуры → приведение к единому виду
→ контроль качества и правдоподобия → юридический compliance → сведение по всем ОП
→ хранение истории и трендов → документы (Excel/PDF/Word/QR/1С) → дисциплина ОП
→ автоматика по расписанию → развёртывание, обновления, диагностика
```

## 1.2. Проблематика (as-is)

| Проблема | Следствие |
|---|---|
| Каждое ОП присылает файлы в своей структуре (свои заголовки, порядок, объединённые ячейки, «коврики» из строк выше шапки) | Ручное сведение 5–15 файлов ежедневно |
| Числа — текстом, даты — строками, NBSP, омоглифы, «Иванов иван» | Ошибки подсчётов, срыв сроков контроля допусков |
| Один человек в двух ОП (двойной учёт) | Дублирование численности, двойная выдача СИЗ |
| Медосмотры/удостоверения истекают незаметно | Риск допуска без действующего документа — юридический риск |
| ПДн (СНИЛС, паспорта) пересылаются без контроля | Риск по 152-ФЗ |
| Вся работа — вручную в Excel | 2–4 часа в день оператора, ошибки, нет истории |

## 1.5. Глоссарий

| Термин | Значение |
|---|---|
| **ОП** | Обособленная площадка — филиал, источник отчётов |
| **Модель листа** | Данные в памяти: матрица значений + параллельная матрица стилей (шрифт, заливка, границы, формат) + ширины/высоты/объединения |
| **Операция** | Функция над моделью листа с параметрами; единица Конструктора; имеет неизменяемый внутренний код `op_id` (§V.0) |
| **Цепочка (сценарий)** | Упорядоченный список шагов `{op_id, version, params}`; сохраняется в JSON |
| **Шаблон дня (job)** | Outlook-приём + цепочка + валидация/compliance + свод + снапшот + документы + письмо + расписание + канал ПДн |
| **Маппинг** | Эталонные столбцы + правила «столбец источника → целевой» по маске имени файла |
| **Ключ человека** | Первичный: нормализованное ФИО + дата рождения (глобально). Fallback: (ОП, таб.№, дата приёма) — составной (FR-1920) |
| **Двойной учёт** | Один человек в реестрах ≥ 2 ОП |
| **DQ-скор** | Оценка качества данных листа, 0–100; нормирована на проверенные строки (FR-1105) |
| **Снапшот** | Сохранённое состояние в накопительном хранилище (история) |
| **Долг по отчётности** | Ожидаемый по календарю отчёт ОП, не полученный в срок |
| **Квитанция** | Автоответ ОП: файл принят, структура проверена, список замечаний |
| **Канал выгрузки ПДн** | Зарегистрированное направление передачи ПДн (получатель, состав полей, основание, срок действия) — М20.1 |
| **Неполный свод** | Свод, собранный при отсутствии ожидаемых файлов/ОП; обязательно помечается и докладывается (FR-0715) |
| **Маркер выполнения** | Файл `state/{job}_{дата}.done` с итогами прогона (FR-2911) |
| **Миграция схемы** | Версионированное обновление структуры хранимых данных (JSON/SQLite) при обновлении приложения (М39) |
| **Отпечаток структуры (fingerprint)** | Нормализованный набор заголовков + типы столбцов + число столбцов |

## 1.6. Ограничение профиля: работа без прав администратора

**Принцип:** система разворачивается и живёт целиком внутри профиля пользователя Windows. Прав администратора ОС не требует **никто и никогда** — ни при установке, ни при обновлении, ни в эксплуатации, ни в headless-режиме. Роль «Администратор» в ТЗ — роль приложения, не права ОС.

### 1.6.1. Что это означает архитектурно

| Область | Решение без прав админа |
|---|---|
| Установка | Inno Setup `PrivilegesRequired=lowest` → `%LOCALAPPDATA%\Programs\ExcelStudioHR\`; ярлыки — в меню Пуск пользователя; portable-режим — распаковка папки (FR-3901) |
| Данные | Всё в `%LOCALAPPDATA%\ExcelStudioHR\` (Часть VIII); реестр — только HKCU; ассоциации файлов — HKCU; автозапуск — Run-ключ HKCU или задача ONLOGON (FR-3920) |
| Обновления | In-place в каталоге пользователя; копия для отката — в `updates\rollback\`; ни один файл системы не трогается (FR-3902, FR-3905) |
| Outlook/Excel COM | Работают в контексте залогиненного пользователя; прав админа не требуют (М6, М18) |
| DPAPI | Шифрование ключей API — per-user, без прав админа (FR-3607a) |
| Headless job | Задача Планировщика Windows **уровня пользователя** — регистрация не требует админа (FR-3920); флаг «выполнять независимо от входа пользователя» с хранением кред в CredMan — тоже без админа |
| IPC-мост (CLI → GUI) | Именованный канал в per-user namespace `\\.\pipe\ExcelStudioHR-{SID}` (FR-2909) |
| Сетевые ресурсы (NAS, `\\fin\…`) | Доступ определяется **доменными** правами на шару, не правами админа локальной машины; проверка — чек-лист Прил. Г, п. 5 |

### 1.6.2. Единственное реальное следствие: SmartScreen неподписанного EXE

Поскольку внутренний сертификат с доверенным корнем требует однократной установки корня в Trusted Root (это требует прав админа и выходит за скоуп), применяются митигации **без прав админа**:

1. **Распространение через интрасеть** — файлы, скачанные из зоны «Местная интрасеть»/доверенных расположений, не получают метки MotW (Mark-of-the-Web) → предупреждение SmartScreen не появляется. Основной канал поставки — внутренний сетевой ресурс или портал, а не интернет.
2. **Разблокировка пользователем** — если MotW всё же есть: ПКМ → Свойства → «Разблокировать» (Unblock) — операция уровня пользователя, не требует админа; при массовом развёртывании — инструкция в поставке.
3. **SmartScreen-reputation экран** — «Подробнее → Выполнить» пользователем; разово при первом запуске.
4. **Если у ИТ есть права администратора (вне обязательного скоупа ТЗ):** внутренний сертификат + GPO/AppLocker — как улучшение, а не условие эксплуатации.

### 1.6.3. Явно вне скоупа (не реализуется и не требуется)

Службы Windows, драйверы, запись в HKLM, планировщик уровня системы, хранение кред под системной учёткой, firewall-правила, WDAC-политики. Если какая-то из этих возможностей понадобится позже — оформляется отдельным заданием ИТ с правами админа и не влияет на данное ТЗ.

### 1.6.4. Проверка профиля

- Самотест «Здоровье» (М30) проверяет отсутствие записей в HKLM и наличие только per-user путей.
- Чек-лист Прил. Г п. 4 фиксирует: у целевых пользователей **нет** прав админа — это подтверждённое условие, а не ограничение.
- Критерии приёмки 1–40 выполняются на машине без прав администратора; ничего в §XIII не требует повышения прав.

**FR-1105 (DQ-скор, нормированная редакция):**

```
penalty_rows = 0.5·R_пустые_обяз + 1·R_формат + 2·R_смешТип + 3·R_дубльКлюч
score = max(0, 100 − penalty_rows / checked_rows × 100)
```

| ID | Требование |
|---|---|
| FR-1105a | `checked_rows` = число строк данных, охваченных хотя бы одной проверкой; скор сопоставим между листами разной ширины |
| FR-1105b | Пример: 10 000 строк, из них проверяемые 8 000; 40 пустых обязательных + 20 форматных + 10 смешанных → penalty = 20+20+20 = 60 → score = 100 − 60/8000×100 = **99.25** |

## М4. Конструктор цепочек

**Действия:** выбор операции из каталога (категории: Структура, Очистка, Исправление, Кадры, Массовые, Валидация, Справочники, ИИ, VBA, Формат, Отчёт) → «➕ В цепочку» → диалог параметров (типы: столбец-комбобокс с заголовками, число, текст, флаг, выбор, справочник, многострочный код; имена параметров — внутренние коды, §V.0.5) → шаги в списке (двойной клик — редактирование, ↑↓ — порядок, ✖ — удалить) → «▶▶ ВЫПОЛНИТЬ на отмеченных листах» или «▶ на текущем».

**Механика выполнения:** для каждого листа: дельта-журнал открыт → последовательное применение шагов → при ошибке: откат листа (по дельтам), запись «✖ причина», партия продолжается → итоговый отчёт ✔/✖ по каждому листу.

**Дополнительно:** условие шага («если строк > N», «если столбец [X] существует»); шаги-отчёты (не меняют данные) помечены; сохранение/загрузка сценария JSON (только `op_id`); импорт/экспорт текстом; панель «Избранное»; **макрорекордер (М35)**.

## М5. Шаблоны маппинга

**Действия:** (1) открыть эталонный лист → «➕ Создать из текущего листа» → имя, категория, целевые столбцы (из шапки, правится); (2) для каждой разновидности файлов ОП: открыть её лист → «✎ Редактировать» → «➕ Для текущего файла» → маска имени подставляется → комбобоксами указать «какой столбец источника → какой целевой» («— пусто —» = не переносить); (3) шаг `apply_mapping` в цепочке: маска выбирается по имени файла автоматически.

**Хранение** `mappings.json`: `{name, category, target[], maps[{pattern, colmap[]}], fingerprints[]}`.

**Авто-подсказка (М35):** при добавлении файла его заголовки сравниваются с отпечатками; если совпадение ≥ 90% с известным типом — предложение с уверенностью в % (подробности и роли — FR-3504).

## М8. Diff (сравнение)

**Действия:** ПКМ по листу → «Сравнить с…» → выбор целевого листа (все открытые), ключевых столбцов (1–3; автоподсказка уникального столбца), игнор-столбцы, «только различия», нормализация чисел/пробелов → «Сравнить» → вкладка-отчёт «DIFF: A vs B»: статус строки (ДОБАВЛЕНА/УДАЛЕНА/ИЗМЕНЕНА/СОВПАДАЕТ) + пары «старое→новое»; подсветка исходных листов (зелёный/красный/жёлтый).

**Метод:** словарь `ключ→строка`, O(n+m); сравнение по столбцам вне игнора.

**Шаблон дня:** `diff_vs_yesterday` — автопара по маске с вчерашним сводом из папки результатов.

## М11. Валидация

**Правила (7 типов):** обязательное поле; диапазон чисел; формат (regex); дата в интервале («не старше 30 дней»); уникальность ключа; значение из справочника; логика строк (формула М13, напр. `[Сумма]=[Кол-во]*[Цена]±0.01`).

**Действия:** вкладка «✅ Валидация» → «➕ Профиль» → правила с параметрами → сохранить (`validation.json`) → «▶ Проверить текущий лист» → список ошибок `строка 214: Кол-во = 15400 (>10000)` → **двойной клик — переход к ячейке**, красная рамка.

**Реакции:** только отчёт / исключить ошибочные строки в лист «ОШИБКИ» / остановить job с уведомлением. Профиль подключается к job (перед сводом).

## М12. Справочники

**Действия:** вкладка «📚 Справочники» → создать/импортировать из листа/файла/вручную; редактор с поиском; хранение `references.json`.

**Использование:** операция `ref_lookup` (ключ→столбец-приёмник; нераспознанные — пометить/по умолчанию); `ref_normalize` («Мск»→«Москва»); валидация (значение ∈ справочник); compliance (списки, пороги); рассылки (ОП→email, ОП→руководитель); коды профессий ОКПДТР (М33); пороги DQ и дисциплины (FR-1105c); **каналы выгрузки ПДн (М20.1)**.

## М13. Формулы

**Синтаксис:** `[Столбец]`, аргументы через `;`, десятичная точка. Функции: `IF, ROUND, CONCAT, LEN, LOWER, UPPER, YEAR, MONTH, DAY, TODAY(), ISNUM, LOOKUP(справочник;ключ;поле)`, арифметика/сравнения.

## М18. VBA-исполнение (при наличии Excel)

**Конвенция обмена:** приложение пишет данные в лист `DATA` (значения+стили), параметры — в `PARAMS` (A=имя, B=значение, с B2); макрос пишет результат в `RESULT` (или правит DATA); листы `RESULT_2…` добавляются как новые листы.

**Действия:** вкладка «Ⓥ VBA-макросы» → импорт .xlsm (автопоиск имён Sub через oletools) / создание нового из кода в редакторе / параметры через диалог → «▶ На текущий лист» → Excel скрыт (`display_alerts=False`), временная копия книги, `app.Run`, чтение результата **с вычисленными формулами**, подмена модели, временный файл удалён, Excel закрыт.

**В цепочках:** каждый макрос = операция `vba_run:<имя>`; гибрид Python+VBA в любом порядке. Непроверенный макрос — подтверждение; журнал запусков; при ошибке — откат листа. Без Excel/на headless — шаг пропускается с предупреждением.

| Провайдер | Транспорт | Ключ |
|---|---|---|

**Режимы передачи данных** (ПДн-политика): `digest_only` (по умолчанию) / `anonymized` (примеры ПДн-столбцов → `***`) / `full` (**жёсткий отказ** при обнаружении ПДн-столбцов и облачном провайдере; полный df — только `local`).

**Функции:**
1. **«Задача → готовая цепочка»**: ИИ получает каталог операций (`op_id` + отображаемые имена) + дайджест + запрос → JSON-план шагов → валидация (существование `op_id`, fuzzy-поиск, приведение параметров: имя столбца → индекс) → предпросмотр → добавление в Конструктор.
2. **Запрос → pandas-код**: код показывается **до** выполнения; namespace `{pd, np, df}` без файловых/сетевых возможностей; результат валидируется; применение с undo (FR-1402c).
3. **Запрос → VBA** по конвенции DATA/PARAMS/RESULT → сразу в библиотеку.
4. **«3 варианта решения»**: pandas / формулы / VBA с плюсами-минусами.
5. **Сводка и аномалии** по дайджесту.

Все вызовы — в фоне, с таймаутом, в журнал (провайдер, режим, размер дайджеста).

## М24. Штат vs факт

**Действия:** раз в период — загрузка штатного расписания (маппинг «Штат») → снапшот-эталон; операция `staff_compare` (выбор эталона) на своде факта → ключ «ОП+Профессия(+Разряд)» → лист «ШТАТ»: **вакансии** (синий), **перегруз** (оранжевый), **вне штата** (красный), **пустая позиция**; режим «по подразделениям»; порог существенности Δ; тренд вакансий из хранилища (М28).

## М25. Табельный учёт

**Вход:** табель узкий (Таб.№, дата, часы, код) или широкий (дни 1..31) — операция `timesheet_unpivot` («развернуть дни в строки») и обратная `timesheet_pivot`.

**Проверки-аномалии:** часы > порога суток (12/24); код отпуска/больничного при часах > 0; часы > 0 без кода; **один человек — один день — две ОП** (аларм «двойная смена/двойной учёт»); расхождение суммы часов с заявленным итогом ОП.

**Расчёты:** ночные (22:00–06:00, параметр) и сверхурочные (сверх нормы смены из справочника профессий) — новые столбцы, суммы без ставок. **Пересечение полуночи:** часы считаются по факту пересечения смены с интервалом (тест-кейс «смена 21:00–07:00 → ночных 8 ч»).

**Выход:** лист «ТАБЕЛЬ-АНОМАЛИИ» + счётчики по типам; включается в job.

## М26. Отпуска

**Функции:** остаток дней (начисление X дн./мес, по умолч. 2.33, от даты приёма − использованное); **пересечение критических специальностей**: ≥ 2 разных людей одной ключевой профессии одного ОП с пересекающимися датами → аларм (справочник «Ключевые профессии ОП»); противоречия «в отпуске в реестре» vs «часы в табеле» (связь по ключу человека с М25); лист «ОТПУСКА-ПЕРЕКРЕСТЬЯ» + экспорт в Word для согласования.

## М35. Макрорекордер и умный маппинг

### Требования

| ID | Требование |
|---|---|

| FR-3504c | Если структура **не распознана**: оператору — «структура не распознана, файл обработан в режиме ручной проверки; задача передана аналитику» (событие в центре уведомлений М29 с ссылкой на файл, эскалация FR-2915); аналитику — карточка «новая структура: fingerprint, отличия от ближайшего известного» |
| FR-3504d | Роль, от лица которой произошло применение/обучение/отклонение, фиксируется в журнале |
| FR-3505 | Библиотека отпечатков — в `mappings.json`; просмотр/удаление в редакторе маппинга |

1. Аналитик включает «⏺», делает привычную обработку нового типа файла (5 операций) → останавливает → «Сохранить как сценарий "Реестр ОП-новый"».

## М38. Проверки правдоподобия (санити-чеки)

### Требования

| ID | Требование |
|---|---|
| FR-3801 | **Контрольные числа**: СНИЛС, ИНН (10/12-значный) — неверный контрольный разряд → аларм «ошибка в номере» (опечатка, не «подозрительный человек») |

1. В очередном реестре ОП-4 санити-чек нашёл: СНИЛС с неверным контрольным числом (12 человек — массовая опечатка при переносе), 2 «Ивановых» с отчеством «-овна» при поле «м».

# ЧАСТЬ VII. СКВОЗНЫЕ СЦЕНАРИИ (каждое действие)

## А. Первый запуск и настройка (≈ 30 минут, один раз)

1. Запуск → онбординг (5 шагов) → каталоги `%LOCALAPPDATA%\ExcelStudioHR\` созданы; создание Администратора (PIN).
2. «📚 Справочники» → импорт стартового комплекта (Прил. А) → **ответственный по приказу** заполняет правовые значения и поля «проверено до» (FR-2301b, FR-2399); регистрируются каналы выгрузки ПДн (FR-2005).
3. «📧» → правило «Приём от ОП»: маски `*реестр*;*допуски*;*медосмотр*;*табель*;*.csv`, папка Входящие/ОП, вложенные ✓, дедуп ✓.
4. По каждому типу отчёта: открыть эталон → «🗂 Создать маппинг из листа» → для каждого ОП — «➕ Для текущего файла» и соответствия столбцов. Отпечатки сохраняются автоматически.
5. «🧩» → собрать цепочку (⏺ можно записать действиями): `autotable → apply_mapping → fio_normalize → sanity_check → text_to_number → str_to_date → deadline_control → dedup_person → style_header`.
6. «⭐» → job «Утренний кадр»: правило+автозагрузка+цепочка+валидация («Сотрудники — контроль», exclude_to_sheet)+compliance («Опасные работы»)+свод «СВОД»+dedup (ФИО+ДР)+снапшот+`D:\Кадры\Своды\Свод_%Y-%m-%d.xlsx`+квитанции ОП (черновик)+email ОТиПБ+**канал «ОТиПБ-своды»**+расписание `daily 08:00`+ожидаемые источники (календарь).
7. Второй job «Еженедельный compliance»: цепочка+compliance+Word-уведомления по «ПРОСРОЧЕНО» (канал «ОП-уведомления»)+рейтинг ОП.
8. «🧾 Экспорт пакета» (с паролем, AES-256) → резервное рабочее место.

## Б. Обычное утро оператора (≈ 5 минут)

1. Приложение в трее с вечера; 08:00 внутренний планировщик выполнил job (мьютекс соблюдён, маркер создан).
2. 🔔(3): `✔ Свод готов (14 213 строк) · ⚠ ОП-3 не прислал реестр — долг 1 дн. · 🔴 Патенты ≤30 дн: 3`.
3. Открыть свод (шапка без пометки «НЕПОЛНЫЙ» — все ОП прислали); двойной клик по ФИО подозрительного → карточка 360° → «медосмотр просрочен на 12 дн.» → клик → ячейка на листе → правка.
4. «Напомнить ОП-3» → черновик письма → отправить. Квитанции просмотреть → отправить.
5. PDF дашборда → руководителю. 14:00 — всё, работа сделана.

## В. Инцидент: файл прислан «криво»

1. Лог job: `⚠ реестр (3).xlsx_new → структура не распознана; задача аналитику создана; файл исключён из свода` (FR-3504c, FR-0715 — свод помечен «НЕПОЛНЫЙ: ОП-5»).
2. Аналитик открывает файл → «🔍»: шапка в строке 5 (коврик из 4 строк), столбец «Кол-во» — текст.
3. «🤖»: запрос «обрежь выше шапки, приведи заголовки, текст в числа» → план из 3 шагов → предпросмотр → применить.
4. В маппинг добавить маску `реестр*оп5*.xlsx` → fingerprint сохранён. Квитанция ОП-5 ушла с замечанием о naming (М32).
5. Если аналитик не принял задачу за 4 часа — напоминание, за день — Администратору (FR-2915).

## Г. Авария

1. Отключение питания на 12-й минуте (автосейв 5 мин).
2. Перезапуск → «Восстановить сессию?» → да → потеря ≤ 5 минут; оригиналы целы; бэкапы на месте.
3. Карточка «последний сеанс завершился ошибкой» → «Собрать диагпакет» (без ПДн) → в ИТ.
4. «🩺 Здоровье» → самотест зелёный → продолжение. Зависший мьютекс job старше TTL — снят автоматически с записью в журнал.

## Д. Ежемесячная сдача в бухгалтерию (≈ 3 минуты, 1 раз в месяц)

1. 1-е число; планировщик (или оператор кнопкой) запускает job **«Месячный кадр → 1С»**.
2. Диспетчер (FR-2906): мьютекс получен; маркера текущего месяца нет — режим `full`.
3. Outlook-приём: не принятые реестры прошлого месяца → в лог; долги — в центр уведомлений.
4. Цепочка: свод факта за месяц → `fio_normalize` → `sanity_check` → `okpdtr_encode`.
5. Валидация «Сотрудники — контроль» → 3 строки в «ОШИБКИ» (исключены из выгрузки), счётчик в отчёте.
6. Экспорт по профилю «1С-ЗУП»: канал «Бухгалтерия-ЗУП» (основание: приказ №___ от ___, срок до 31.12.___, проверен FR-2007) → `\\fin\1c_upload\kadry_2025-05.csv` (cp1251).
7. Запись в журнале выгрузок ПДн: канал, основание, файл, 14 213 записей, состав столбцов.
8. Письмо в бухгалтерию (черновик): «Выгрузка за май готова: 14 213 записей, исключено 3 (см. ОШИБКИ)».
9. Снапшот; квитанции ОП с замечаниями — в черновики; лог ✔ по шагам; маркер `.done`.

## Е. Обновление приложения (раз в 1–3 месяца)

1. ИТ размещает новый пакет на сетевом ресурсе (проверка обновлений включена, источник настроен).
2. Администратор получает уведомление «доступна версия X.Y» с журналом изменений.
3. «Обновить» → скачивание → **проверка SHA-256** из манифеста → автоматическая копия каталога данных → установка → первый старт: **миграции схем** (`schema_version` каждого файла) → самотест → «Здоровье» зелёное.
4. Откат при неудаче: восстановление каталога данных из копии; старая версия EXE сохранена в `updates\rollback\`.

# ЧАСТЬ XIII. КРИТЕРИИ ПРИЁМКИ

## 13.1. Критерии 1–25 (базовые)

1. **Форматы:** совпадение ≥ 99% **на ячейках с явными rgb-цветами** с эталоном Excel на 3 контрольных книгах (режим «Перечитать с полными форматами»); ячейки theme/indexed — отдельный счётчик допусков (разница оттенка tint ≤ порога, настраивается); условное форматирование и диаграммы — вне скоупа (задокументировано).
2. **Партия:** цепочка 12 шагов × 20 листов × 10 файлов — отчёт по каждому листу; оригиналы нетронуты; бэкапы созданы; undo каждого шага ≤ 1 с (FR-1402d).
3. **Объём:** 200 000×20 — ≤60 с загрузка (ленивые стили); правка на 47-й странице пишет в верную строку модели; стили страницы ≤ 0,5 с; **сохранение с неполными стилями вызывает диалог FR-0103e, default — «Перечитать»**.
4. **Двойной учёт:** 50/50 заложенных кейсов (регистр, «ё», пробелы, форматы ДР); без ДР → «НА ПРОВЕРКУ»; **составной fallback-ключ (ОП+таб.№+приём) не склеивает людей разных ОП** (FR-1920b); ручная склейка через person_links применяется в следующем своде.
5. **Сроки:** прогон с «Дата отсчёта = 05.06.2025» (FR-1910b) — воспроизводим вне зависимости от даты приёмки: «15.06.2024» (12 мес.) = красный; «20.06.2024» = жёлтый; «15.01.2025» = чисто; **краевые: 31.01+1м → 28.02, 29.02.2024+12м → 28.02.2025, 31.10+1м → 30.11, 30.01+1м → 28/29.02**.
6. **Падежи:** ≥ 98% на контрольных 200 ФИО; спорные помечены.
7. **Compliance:** несовершеннолетний+вредная профессия найден; патент «завтра» — жёлтый; пустой ВУС призывника — аларм; группа ЭБ ниже требуемой — аларм; **значения порогов взяты из справочника, заполненного ответственным** (FR-2301b).
8. **Штат:** тест с вакансией 6 / перегрузом 1 / вне штата 2 — все категории посчитаны.
9. **Табель:** двойная смена двух ОП в один день найдена; 26 ч найдено; расхождение с итогом показано; **смена 21:00–07:00 → ночных 8 ч**.
10. **Отпуска:** 2 стропальщика одного ОП с пересечением дат → аларм; противоречие «отпуск/часы» найдено во всех 5 заложенных случаях.
11. **Word/QR:** 30 уведомлений из «ПРОСРОЧЕНО» с корректной подстановкой; проходной лист с QR открывается Word; **файлы с ФИО созданы только при указанном канале ПДн**.
12. **Дашборд:** после 3 снапшотов тренд численности строится; Δ мес-к-мес сходится с ручным расчётом; отсутствие индексов → «Здоровье» показывает предупреждение и пересоздаёт.
13. **Календарь:** неполученный отчёт → «долг 2 дн.» → черновик-напоминание; после приёма долг снят.
14. **Конфигпакет:** перенос на чистую машину → всё работает; конфликты имён решены диалогом; **пакет без пароля/с ZipCrypto — отказ при импорте** (FR-3604a).
15. **VBA без Excel:** извлечение → вставка в другой .xlsm → oletools подтверждает; backup есть; Excel отсутствовал.
16. **ИИ×ПДн:** mitm-перехват при `anonymized` не содержит ФИО/СНИЛС; `full`+ПДн в облако → отказ.
17. **Авария:** сбой питания → потеря ≤ 5 мин; оригиналы целы; краш-карточка и диагпакет сформированы без ПДн.
18. **Headless:** `--run-daily` первый прогон → свод, письмо-черновик, маркер `.done`, лог чист; **повтор в тот же день** → по умолчанию режим `data`: свод `_v2`, письмо и квитанции **не дублируются**; запуск при идущем job → код 3; запуск при открытом GUI → команда ушла в GUI, код 0, результат по маркеру (FR-2909).
19. **М34:** вставка таблицы из письма → лист; операция «на выделение» не затронула остальные строки; копирование ПДн в буфер → диалог FR-2020.
20. **М35:** файл с известным отпечатком → подсказка ≥ 90% одним кликом (аналитик); роль «Оператор» — read-only + применение существующего маппинга; нераспознанная структура → событие аналитику автоматически.
21. **М32:** квитанция содержит замечания из диагностики и **не содержит** значений ПДн; повторная квитанция при неизменных замечаниях не формируется (FR-2914, FR-3207).
22. **М38:** СНИЛС с неверным контрольным числом найден во всех 12 заложенных случаях; пол/отчество 100/100 на контрольной выборке; санити дат: приём в 13 лет — жёсткий аларм.
23. **М36:** второй GUI-экземпляр не запускается; простой 10 мин → экран заблокирован; роль «Оператор» не видит редакторы; **запись с устаревшими PBKDF2-параметрами → принудительная смена пароля** (FR-3601a).
24. **М31:** карточка по человеку из 4 листов и 2 снапшотов собрана ≤ 2 с; переходы к ячейкам верны; ручная склейка «Это один человек?» — в журнале и person_links.
25. **1С:** файл профиля 1С загружен в тестовую базу ЗУП без ручных правок; лист `_meta` присутствует; запись в журнале выгрузок полна.

### Резюме

Система закрывает **весь цикл**: приём (Outlook/папки/буфер) → распознавание и приведение → контроль качества и правдоподобия → юридический compliance → сведение (с контролем полноты) → хранилище и тренды → документы (Excel/PDF/Word/QR/1С) → дисциплина ОП (квитанции, рейтинг, календарь, эскалация) → автоматика по расписанию (таймер + headless CLI с мьютексами и защитой от дублей) → ПДн-контур (каналы с основаниями, журнал, трассировка) → развёртывание, обновления, миграции, телеметрия и тестовый контур. **41 модуль, 65+ операций (с внутренними кодами op_id), 40 критериев приёмки, 7 этапов (MVP — этапы 1–4).**

Готов следующим шагом выдать: **(а)** генератор тестовой базы 200 000 строк со всеми заложенными ошибками для приёмки по §XIII (модуль М41), **(б)** код любого модуля в готовом для вставки виде, или **(в)** стартовый комплект «под ключ» одним скриптом (справочники + маппинги + 2 job).
